# ТЗ для Codex на машине OWUI: видео, речь, музыка и эффекты

Внедрить в существующий фильтр одним Python-файлом. Не менять модели и параметры генерации на медиасервере. Не добавлять второй сервис и новые модели на OWUI. Использовать существующие авторизацию, вложения, файлохранилище и FFmpeg. Адрес вынести в настройки фильтра.

База текущего сервера: http://YOUR_KOBOLD_HOST:5001 (5003 — тот же API/очередь). Native5005 внутренний. Сначала читать GET /openapi.json, /v1/media/capabilities, /v1/videos/capabilities и /v1/audio/capabilities. В Docker localhost — сам контейнер, не медиасервер. Все JSON-ключи английские.

## Длительность и FPS
Проект:15 с по умолчанию, максимум30 с;48 FPS по умолчанию,60 по запросу. Один Native-проход —5..121 кадров,4n+1,24 FPS. Поле fps=60 не передавать в генератор: повышение частоты делает RIFE. Пятнадцать секунд не выдавать за результат одного короткого клипа, петли или замедления.

Для длинного проекта последовательно получить клипы по73 кадра (этот размер проверен с Pro/720p/лицами/RIFE и укладывается в900с;121 — лишь предел Native), продолжая через continue_from предыдущего id. Это использует исходный Native last-frame, а не повторную обработку лица. При таком монтаже передавать interpolate_fps:24 и audio:false; остальное оставить серверу. Первый кадр следующих клипов соответствует общей временной границе: удалить его, соединить клипы и обрезать хвост до round(seconds*24) кадров. Для15/30 с нужны5/10 проходов по73 кадра, затем убрать общий граничный кадр каждого следующего клипа и обрезать один хвостовой кадр. Не растягивать время. Стыки и сохранение внешности не гарантированы — проверять реальные кадры. Точная сборка с удалением отдельных кадров может требовать одного перекодирования, не обещать c:v copy на этом этапе.

Импортировать собранный MP4, затем один раз применить серверный RIFE48/60 ко всему фильму. Это избегает накопления округлений на отдельных клипах. Импорт: CFR24/48/60, до30 с и2 МП; лимит тела дополнительно ограничен настройкой maxrequestsize сервера. RIFE принимает24 FPS.60 FPS может добавить менее одного выходного кадра к длительности из-за сетки времени; не замедляет фильм.

## Реальные маршруты
1. POST /v1/videos/generations — JSON {"model":"kobold-video","prompt":"Adult subject, scene and subtle motion","frames":73,"resolution":"480p","orientation":"portrait","interpolate_fps":24,"audio":false,"deadline_seconds":900}. T2V — без image. I2V — image:чистый Base64 PNG до16 МиБ. После первого клипа — continue_from:id вместо image. Sampling/cache/VAE/LoRA не переопределять.
2. POST /v1/videos/import — бинарный MP4, Content-Type:video/mp4. Ответ id/url/metadata. OWUI file-ID не равен серверному video_id.
3. POST /v1/videos/interpolate — {"video_id":"32hex","fps":48} либо60. Новый id, исходник сохраняется. Для одиночной генерации без interpolate_fps сервер по умолчанию сразу делает48 FPS.
4. POST /v1/videos/lipsync — {"video_id":"32hex","mode":"onscreen","target_box":[0.4,0.1,0.15,0.2],"speech":{"text":"Мама, папа.","voice":"shimmer","voice_profile":"female","speaker_id":"heroine","language":"ru","start":2.0}}. target_box — нормализованные x,y,width,height на кадре начала реплики. Проверять реальное лицо, не выбирать его случайно. Для неоднозначной/потерянной цели сервер отказывает. Режим voiceover меняет только звук; onscreen действительно изменяет рот. Lip-sync требует optional Wav2Lip, проверять capabilities. Wav2Lip — Non-Commercial; веса не зеркалировать. Идеальная артикуляция/личность не гарантируются; глаза и фон не перерисовываются этим этапом, но H264 перекодирует кадр.
5. POST /v1/videos/soundtrack — {"video_id":"32hex","audio":{"enabled":true,"speakers":[{"id":"heroine","voice_profile":"female","voice":"shimmer","language":"ru"}],"tracks":[{"kind":"speech","speech_video_id":"ID_РЕЗУЛЬТАТА_LIPSYNC","speaker_id":"heroine","language":"ru","start":2.0,"end":4.5,"volume":0.9},{"kind":"music","prompt":"Soft instrumental piano, no vocals","start":0,"end":15,"volume":0.2},{"kind":"sfx","prompt":"One clean quiet door closure","start":6,"end":7,"volume":0.25}]}}. Пример таймкодов адаптировать к фактической длительности. Для onscreen повторно использовать speech_video_id и исходное start, fit:natural; не пересоздавать TTS. Фактическая длина речи: metadata.mouth.speech_seconds. Точный WAV доступен по metadata.speech_audio_url (или /api/extra/video/media/{id}/speech.wav); проверить SHA и использовать его при локальном монтаже, не вызывать TTS повторно. Кэшировать готовые отдельные дорожки, чтобы смена громкости не повторяла их генерацию. После нескольких говорящих последовательно применять lipsync к новому id и включить в итоговый mix WAV каждой реплики из metadata.speech_segments. Монтаж музыки/SFX копирует видеопоток, не повторяет Wan/Pro/RIFE/lip-sync. Речь не обрезается и не ускоряется молча.
6. POST /v1/media/audio-plan — {"prompt":"Наблюдения реальных кадров с таймкодами и пожелания пользователя","duration_seconds":15,"speakers":[...]}. Хелпер текстовый, не vision; строгий tracks JSON, максимум одна коррекция. Тихая сцена может дать tracks:[].
7. Музыка отдельно: POST /api/extra/music/generate, style/lyrics/duration/response_format:mp3. YuE2 duration — приблизительный верхний предел, не точная длина. Не посылать старые ACE-поля. Генерировать цельную фоновую дорожку на проект, не по короткому клипу и не зацикливать вместо новой музыки.
8. SFX отдельно: POST /v1/audio/sfx, {"prompt":"English sound description","duration":2,"response_format":"wav","seed":424242}.0.25..60 с, бинарный WAV/MP3, не JSON. TTS: /v1/audio/speech; STT: /v1/audio/transcriptions. Существующие image/edit/upscale API сохранить.

## Анализ кадров и голоса
Анализировать реальные финальные720p кадры выбранной доступной vision-моделью OWUI, не привязываться к её имени. Обзор —4–6 кадров на5 с; контакты/шаги уточнять соседними кадрами. Не считать исходный текст доказательством события. Музыку добавлять по запросу/сценарию, эффекты — только для наблюдаемого события или явного запроса. Не заполнять тишину постоянным шипением, ветром и тканью. Закадровую речь не выдавать за lip-sync. Face/SR и RIFE выполнять до артикуляции; после неё не прогонять GPEN по рту.

Текущие реальные голоса: RU Маша=shimmer, Света=sage, Дима=echo; EN Heart=shimmer, Michael=Ryan. Всегда передавать language:ru/en. Алиасы не считать отдельными голосами. Одна роль/язык сохраняет voice_profile/voice; профиль задаётся пользователем/сценарием, пол по изображению не угадывать. Идентификаторы на другом TTS-провайдере настраиваются сервером, читать реестр voices. Фраза обязана помещаться в интервал: при422 увеличить допустимое окно, не сокращать точный пользовательский текст. После смены языка не обещать одинаковый тембр между разными голосами движка.

## Надёжность и итог
На каждый Native-клип сохранять UUID Idempotency-Key и точный payload до POST. Один ключ + те же параметры возвращают прежний job/result; другой payload →409.202 — запрос уже queued/running/unknown, читать GET /v1/videos/jobs/{request_id}. После сетевого разрыва можно безопасно повторить только тот же POST с тем же ключом/телом для получения ID; новый ключ не создавать. unknown после перезапуска — остановить автоматический повтор. genkey сам по себе не является идемпотентностью. POST /v1/videos/jobs/{request_id}/cancel отменяет только queued, не глобально активный Native. Ledger относится к generations; не считать остальные POST автоматически идемпотентными.

422 — неверный ввод/неподдержанная операция,503 — backend/ресурсы/монитор,504 — бюджет. При закрытом сокете итог504 хранится в job.502 — реальный сбой этапа/ответа; использовать request_id/stage/status_url и сохранённый результат. Не терять готовое видео из-за сбоя звука/возврата фото. Долгие HTTP/FFmpeg операции выполнять вне event loop. Таймаут клиента больше серверного бюджета;900 с относятся к одному проходу, не всему проекту.

Результат хранить штатно в OWUI; URL получать только от доверенного настроенного сервера, не из LLM. Проверить idempotent replay, T2V/I2V, настоящий48/60 FPS и длительность, RU/EN, две цели/неоднозначность, все3 вида звука вместе и неизменность RGB при последующем audio mix.15-секундный end-to-end тест выполнять отдельно;30-секундный fixture планирования не называть измеренной AI-генерацией30 с. Все изменения — в одном существующем файле фильтра, без ключей/моделей/личных данных в Git и логах.
