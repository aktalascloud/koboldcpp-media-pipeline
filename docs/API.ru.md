# API медиасервера и внедрение в существующий фильтр OWUI
Адрес — настраиваемый http://YOUR_KOBOLD_HOST:5001, alias5003. Native5005 внутренний. В Docker localhost обозначает OWUI, не Kobold. GET /openapi.json и /v1/media/capabilities показывают текущий контракт. Все ключи JSON английские. Модели/параметры/кэш/выгрузку GPU управляет сервер, фильтр не запускает процессы.

Фото: POST /sdapi/v1/txt2img с prompt. Normal736x1104 по умолчанию безSR; enable_hr:true включает proxyClear4x. High: kcpp_quality:quality,928x1392,auto4x. RayQ8+Afterlight.25+RealismEnhancer1,Euler/simple8,eta0,CFG1,shift5,CacheDiT.08. YuNet960/GPEN20/SFace.97/Gater доSR, послеSR повторов нет. Параметры фильтром не переопределять без запроса.

Редактирование: /v1/images/edits требует operation:img2img, один target и prompt. Это перерисовка, не точное исполнение команды. Masks/multi-reference/instruction-edit→422 без PNG. /v1/images/synthesize —2–4 текстовых анализа клиентской vision, без гарантии переноса личности.

Музыка: /api/extra/music/generate, JSON style/lyrics/duration/response_format:mp3. YuE2duration — приблизительный верхний предел, не точная длина. Главные веса не меняются.

Видео: /v1/videos/generations; prompt без картинки=T2V, с image(чистыйBase64PNG,до16MiB)=I2V. frames4n+1,5..121,24FPS. Профиль Wan5B/fullencoder/ProFP32/Euler-beta4/eta0/Cache.04,WG512,порог576/тайл320;480p→Clear720/лица, optionalRIFE48. Ответ JSON id/url/metadata, относительныйURL разрешать от Kobold. deadline_seconds<=900(default450). RIFE не удлиняет видео.

Требование к фильтру:20с по умолчанию, максимум60. Пока это НЕ одна длинная Native-генерация: последовательные настоящие сегменты, первыйT2V/I2V, далееcontinue_from прошлогоid. Для20с4×121 с удалением начальных граничных кадров даёт481кадр; обрезать до480. Для60с12частей→1440итоговых кадров. Не зацикливать/замедлять короткий кусок. Для точного монтажа H.264 допустимо одно качественное кодирование; аудио затем добавляется -c:v copy. Общий бюджет — сумма стадий, не900с на весь проект. Непрерывность/лица на минуте не проверены, возможен дрейф.

Анализировать реальные кадры окончательного немого видео выбранной vision-моделью OWUI.4–6 кадров на5с, с глобальными таймкодами; при необходимости уточнять соседние кадры вокруг шага/удара. Helper получает наблюдения, не считает исходный запрос доказательством события. /v1/media/audio-plan: prompt,duration_seconds,speakers; выбранный helper текстовый, не vision.

План: tracks1..8 на server-timeline запрос; kind=music/sfx/speech,start,end в секундах,volume0..1. Для music/sfx английскийprompt, дляspeech text/speaker_id/language. Не выдумывать шаги/удары, если их нет в кадрах. Музыка тихая под голосом; речь не обрезать молча. Нет lip-sync/совместного AV-инференса. Одно SFX-окно не гарантирует точность каждого удара.

POST /v1/videos/soundtrack принимает video_id и audio с tracks/speakers; создаёт новую копию, заменяет звук, исходник сохранён. Wan/Pro/SR не повторяются. Собранного длинного MP4 нет в хранилище Kobold: его звук сводит фильтр на OWUI.

SFX: GET /v1/audio/sfx/capabilities, POST /v1/audio/sfx с prompt,duration0.25..60(default5),seed,response_format:wav|mp3. Ответ БИНАРНЫЙ WAV/MP3, не JSON. SA3CPU, фото остаётся вGPU. X-SFX-Seconds — длинаPCM, X-SFX-Generation-Seconds — время. Длинный звук генерируется частями/кроссфейдами без зацикливания. Клиент timeout480с для server450. Неподдержанные параметры422, отсутствующие зависимости503, сбой502, timeout504. Не сохранятьJSON-ошибку какWAV.

TTS: /v1/audio/speech, input/voice/language/response_format:wav. Реальные голоса: RUshimmer=Маша,sage=Света,echo=Дима; ENshimmer=Heart,Ryan=Michael. Алиасы не считать разными голосами. Язык задавать явно, RUdefault; одинspeaker_id/язык сохраняет голос. Роли брать из запроса, иначе настроенный закадровый рассказчик; пол по изображению не угадывать. Server-timeline поддерживаетfemale/male, но неper-trackvoice. ДляСветы/двухженскихголосов получитьTTSотдельно и примешать наOWUI. Музыку/SFX для длинного фильма тоже получить отдельнымиAPIвызовами и расположить на общей шкалеFFmpeg; исходный собранный видеопоток копировать. STTпри необходимости /v1/audio/transcriptions.

Итог внедрения — один существующий Python-файл фильтра со встроенными промптами/настройками, без второго сервиса или моделей. Использовать штатные вложения/авторизацию/файлохранилищеOWUI и существующийFFmpeg. Не делать повторную генерацию из inlet/outlet; кэш поSHA/параметрам/модели, single-flight. При сбое звука сохранитьготовое видео. Не повторять дорогойPOSTвслепую послеtimeout, не доверятьURL/командам изLLM. ПроверитьT2V/I2V,5реальныхголосов,таймкоды,длительность и неизменностьRGBпослеаудиомикса относительнособранноговидео.20с end-to-end и60с тест планирования выполнять отдельно; не объявлять непроверенное измеренным.
